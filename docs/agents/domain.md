# Domain docs

Layout: single-context.

- Domain model: `CONTEXT.md` at the repository root.
- Architecture decision records: `docs/adr/`.

Read `CONTEXT.md`, when present, before domain modeling,
design, or implementation work. Read relevant ADRs before
changing behavior or architecture covered by those decisions.

Preserve established domain terminology. Update domain docs
when an authorized change alters the domain model. Record
significant architectural decisions in `docs/adr/`.

If domain docs are missing, inspect the code and ask about
unresolved domain assumptions rather than inventing facts.
