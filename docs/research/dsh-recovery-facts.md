# DSH startup and recovery facts

Read-only source inspection on 2026-11-10. Pin: `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`. No builds or runtime experiments. Supports [Define the minimal base and local foundational plugin boundary](https://github.com/isning/mygo-int/issues/2); does not resolve that decision independently.

## Confirmed behavior

- **Framework-free bootstrap:** `AppWebEntry` constructs `BootPage` before creating the client Cordis tree. It creates the module system, boots entries, audits activation, then hands the mount point to the plugin-provided `uiRenderer`. The bootstrap page can display progress and plain-text failure without React or functioning UI plugins. It has no retry, plugin manager, configuration picker, or automatic repair controls. [Boot kernel](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/web/src/boot.ts), [Boot page](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/web/src/boot-page.ts).
- **Activation audit:** present entries in the Web client's fixed required-name set must activate. Missing names absent from the manifest do not themselves fail the audit. A required inactive entry rejects startup; optional inactive entries produce a warning and leave active siblings running. The required set includes modules, session controller, renderer, layout, session, chat, and sidebar. This is DSH Web composition policy, not a universal Cordis requirement. [Boot client](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/web/src/boot-client.ts).
- **Plugin-based application:** mount depends on the `uiRenderer` service and remounts when it is replaced. The renderer assembles the application through the `root` Slot. [Mount](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/web/src/mount.ts), [Renderer](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-renderer/src/client/index.ts), [App assembly](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-renderer/src/client/app.tsx).
- **Desktop carrier recovery:** Web bootstrap failure is forwarded through desktop IPC; main-process startup failures, backend error state, main-frame load/preload failures, and abnormal renderer exit also enter native fatal recovery. The first fatal report owns the recovery flow. A best-effort diagnostic is written, with at most one second spent waiting before opening an Electron OS-native error message box. User choices are exit, restart, disable third-party plugins then restart, and retrieve/reveal the diagnostic report when available. Address-in-use failures omit the disable-plugins choice. Recovery-operation failure returns to the dialog. Disabling is explicit, not automatic. During shutdown failures are recorded without opening a dialog. [Web entry](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/web/src/main.ts), [Desktop main](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/desktop/src/main.ts), [Native fatal recovery](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/desktop/src/fatal-recovery.ts).
- **Profile repair:** desktop `disableAllPlugins()` stops short of loading application resources and delegates a locked profile sanitization with the shipped Web bundle set. Its contract says it backs up the profile patch and disables third-party bundles; the Host must be stopped first. This is not a full native plugin-management application. [Project manager](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/apps/desktop/src/project-manager.ts#L70-L77).
- **Runtime Slot failures differ:** per-entry React error boundaries report registrant errors and contain them. Shadowing kinds can abdicate to another registration; HOC failure can expose inner content; a depleted cell yields an error anchor. At Root, no registration throws `SlotAssemblyError`, whereas registrations that all crash yield an empty `data-slot-error="root"` anchor. Assembly errors deliberately escape entry boundaries. The inspected sources do not establish that every post-mount assembly error or empty Root automatically triggers desktop fatal recovery. Ordinary contained Slot failure does not directly invoke it. [Slot renderer](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-renderer/src/client/scoped-slots.tsx).

## Interpretation for mygo (proposal, not an additional user decision)

“Follow DSH” supports a layered boundary: a small bootstrap status/failure reporter independent of product UI plugins; composition-owned required-entry audit; plugin-owned application/root and local render-error containment; and platform-carrier fatal diagnostics/restart/manual repair using OS facilities. It does **not** imply adding a full fixed native recovery application, automatically disabling plugins, or promising a configuration picker. Preserve the user's confirmed replaceable local startup composition; DSH's hard-coded Web required-entry names are evidence of its implementation, not names or business semantics to copy into mygo's base. Android and other carrier-specific recovery presentation, post-mount fatal escalation, and exact repair policy remain later contract decisions.
